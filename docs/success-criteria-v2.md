# 福笑いの成功判定 v2

## 変更の理由と訂正

旧判定は口の中心が目標から15mm以内なら、口が傾いて枠から大きくはみ出しても通過した。口を枠内に収める目的に合っていなかったため、「最終1/5成功」というタスク成功の報告を撤回する。

保存済みの最終5件は新判定で**0/5**。旧成功seed2026102301の最終状態は、中心ずれ14.492mm、回転37.450度、輪郭ずれ上限26.130mm。アームの離脱は成立していたが、口の配置は失敗だった。

## 全て満たす条件

| 項目 | 条件 |
|---|---|
| 中心 | 目標から3mm以内 |
| 面内の向き | 正しい向きから5度以内。180度反転も失敗 |
| 台紙に対する傾き | 5度以内 |
| 輪郭 | 正解位置の唇輪郭と実際の輪郭の双方向のはみ出しが2mm以内 |
| 接地 | 口中心の高さが台紙上面＋口の厚さの半分から2mm以内 |
| アームの離脱 | toolが台紙上面から40mm以上 |
| 保持 | 全条件が同時に1 simulation秒以上継続 |

点線は途切れているため、点線の各画素を領域として扱わず、目標位置・正しい向きに置いた実際の唇メッシュの輪郭を基準にする。描かれた点線を画像から抽出した採点ではない。2mmは線幅・形状近似の許容であり、中心だけで代用しない。世界の絵や物理は変更していない。

輪郭は見た目の`lips_top.dae`から読み、辺上を最大0.5mm間隔で標本化して相手輪郭の各線分への距離と内外を計算する。実際の輪郭から正解輪郭へ、正解輪郭から実際の輪郭への両方向を検査し、標本間の距離を見落とさないよう0.25mmの保守的な上限を加える。位置・回転・高さはsimulatorの採点用poseから計算し、方策への入力には渡さない。

規則・輪郭のSHA256を結果と評価protocolへ保存。別基準のoutputを再開・再集計する操作は拒否する。0.2秒を超える採点サンプルの欠落は保持を途切れさせ、姿勢情報がない場合は成功と推測しない。

## 既存データとの関係

- 旧result.json、summary.json、動画、モデル、元130件は変更・削除しない。
- 再判定は各episodeの`rescore_mouth_outline_v2.json`、集計は`data/evaluation/rescore_v2_final_20261023.json`へ保存。
- 保存された観測時刻に最も近いROS bagの姿勢を50ms以内で照合し、記録関節から離脱高さを再計算した。新たなGazebo rolloutではない。
- 旧130件のacceptedラベルは旧位置基準であり、新しい成功例としては未監査。再学習する前に新基準で品質を分類する必要がある。
- 新しいカメラ教師の最終採用チェックもv2を使用。収集先の既定を`data/expert_images_v2`へ分け、旧manifestの再利用を拒否する。
- 教師制御そのものは従来の12mm視覚停止閾値を持つため、そのままv2の良質なデータを量産できるとは限らない。今回は判定を修正し、新規収集・学習・実行試験は開始していない。次は位置と向きを整える教師制御を検討する。

## 確認したこと

- 正しい配置は通過し、14.5mmずれ、30度/180度回転、傾き、未離脱、浮いた口は失敗する。
- 中心3mm以内でも輪郭2mmの条件を外す場合は失敗する。
- 1秒保持、途中逸脱、採点時刻の欠落、不正なquaternionを検査した。
- Macと実行先Ubuntuコンテナの両方で単体テスト9件が通過。変更Pythonの構文検査、git diff検査。
- 旧最終評価outputの再集計を試し、基準変更によって拒否されることを確認した。原結果は保存。
